# Local AI (الذكاء المحلي)

## الهدف

إضافة نموذج ذكاء اصطناعي حقيقي يعمل داخل Browser (المتصفح) على جهاز المستخدم دون API (واجهة برمجية) مدفوعة ودون إرسال Prompt (التعليمات/المهمة) إلى مزود نموذج مدفوع.

## المسار المعتمد تجريبياً

- Engine (المحرك): `@mlc-ai/web-llm` 0.2.82.
- Engine License (ترخيص المحرك): Apache-2.0.
- Model (النموذج): Qwen3-0.6B.
- Model License (ترخيص النموذج): Apache-2.0.
- Browser Model (نسخة المتصفح): `Qwen3-0.6B-q4f16_1-MLC`.
- Device (طريقة التنفيذ): WebGPU (تسريع بطاقة الرسوميات عبر المتصفح).
- Quantization (التكميم): `q4f16_1`.
- WebLLM upstream estimate (تقدير WebLLM): نحو 1403 MB من VRAM (الذاكرة الرسومية) لهذا النموذج، ومصنف `low_resource_required` في قائمة النماذج الرسمية للإصدار 0.2.82.
- Model Download (تنزيل النموذج): تنزيل كبير بمئات MB عند أول استخدام؛ لا نعرض رقماً دقيقاً حتى نقيس التنزيل الفعلي على الجهاز المستهدف.

## لماذا 0.2.82 وليس الأحدث؟

الإصداران 0.2.83 و0.2.84 لديهما بلاغ حديث عن Regression (تراجع/خلل) يمكن أن يؤدي إلى WebGPU device hang (تعليق جهاز WebGPU) على بعض البطاقات عند prompts أطول. البلاغ يذكر أن 0.2.82 غير متأثر في البيئة المختبرة. لذلك نثبت 0.2.82 إلى أن يُحل الخلل ونكرر الاختبارات.

## لماذا رفضنا Transformers.js؟

جربنا `@huggingface/transformers` 4.2.0 على فرع تجريبي. البناء نجح، لكن `npm audit --omit=dev --audit-level=high` كشف ثغرات High (عالية) بلا إصلاح متاح في تبعيات إنتاج، منها:
- `adm-zip` عبر `onnxruntime-node`.
- `sharp` عبر ثغرات موروثة من `libvips`.

لذلك لم نخف التحذير ولم نتجاوزه؛ تم استبدال المسار قبل الدمج.

## قواعد الخصوصية

1. تنزيل ملفات النموذج يحتاج إنترنت أول مرة أو عند فقد Cache (الذاكرة المؤقتة).
2. الضغط على زر Download Local AI (تنزيل الذكاء المحلي) هو موافقة صريحة على تنزيل النموذج.
3. لا يبدأ تنزيل النموذج تلقائياً عند فتح التطبيق.
4. نص المهمة وتعليمات الوكيل لا تُرسل إلى Paid Model API (واجهة نموذج مدفوعة).
5. التوليد يتم داخل Web Worker (عامل ويب) على الجهاز باستخدام WebLLM.
6. Local AI لا يمنح الوكيل أي Tool Permission (صلاحية أداة) إضافية.
7. Zero-Cost Gate (بوابة التكلفة الصفرية) تبقى مطبقة قبل كل Run (تشغيل).

## التوافق

WebGPU ليس مضموناً على كل هاتف أو Browser (متصفح). لذلك:
- نفحص وجود WebGPU قبل عرض القدرة كجاهزة.
- إذا لم يتوفر، يبقى Local Demo Runtime (المحرك التجريبي المحلي) متاحاً.
- لا نعد المستخدم بأداء ثابت قبل Device Benchmark (اختبار الجهاز).
- لا نجعل Local AI المسار الافتراضي قبل اختبار هاتف حقيقي.

## الأمان والتبعيات

وجود ترخيص حر لا يعني أن التبعية آمنة تلقائياً. قبل الدمج في `main` يجب أن ينجح:
- TypeScript Build (بناء تايب سكربت).
- Production Build (بناء الإنتاج).
- `npm audit --omit=dev --audit-level=high`.
- Zero-Cost validation (فحص التكلفة الصفرية).

إذا ظهر High/Critical Vulnerability (ثغرة عالية/حرجة) في مسار الإنتاج، لا تُدمج التبعية حتى الإصلاح أو الاستبدال.

## المرحلة التالية بعد نجاح الدمج

- اختبار فعلي على iPhone/Safari (آيفون/سفاري).
- قياس وقت تنزيل النموذج وحجمه الفعلي.
- قياس Peak Memory (أقصى استهلاك للذاكرة).
- قياس Tokens per Second (الوحدات النصية في الثانية).
- اختبار العربية.
- اختبار prompts طويلة للتأكد من عدم ظهور مشاكل WebGPU.
- مقارنة النموذج ببديل أصغر إذا كان استهلاك الذاكرة غير مناسب.
