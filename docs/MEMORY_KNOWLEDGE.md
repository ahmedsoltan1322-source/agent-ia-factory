# Phase 2 — Memory & Knowledge (الذاكرة والمعرفة)

## الهدف

إعطاء كل Agent (وكيل) ذاكرة وسياقاً معرفياً يعملان محلياً على جهاز المستخدم وبتكلفة إلزامية 0$، دون قاعدة بيانات مدفوعة ودون رفع ملفات المعرفة إلى خدمة خارجية.

## المكونات

### Session Memory (ذاكرة الجلسة)

- توجد في React state (حالة التطبيق) فقط.
- منفصلة لكل Agent.
- تحتفظ بآخر 8 تفاعلات ناجحة كحد أقصى.
- لا تبقى بعد إغلاق/إعادة تحميل التطبيق.
- لا تُرسل إلى خدمة بحث خارجية.

### Long-Term Memory (الذاكرة طويلة الأمد)

- تُخزن محلياً في Browser localStorage (تخزين المتصفح المحلي).
- منفصلة حسب Agent ID (معرف الوكيل).
- تدعم إدخال Memory (ذاكرة) يدوياً.
- تحفظ نسخة مختصرة من التشغيل الناجح تلقائياً.
- الحد الحالي 60 عنصراً لكل وكيل لتجنب نمو التخزين بلا حدود.

### Knowledge Files (ملفات المعرفة)

الإصدار الأول يدعم الملفات النصية فقط:
- `.txt`
- `.md`
- `.json`
- `.csv`

القواعد:
- الحد الحالي للملف: 700 KB.
- الحد الحالي لإجمالي النص المفهرس: 2.5 مليون حرف.
- الملف يُقرأ داخل Browser (المتصفح) بواسطة `File.text()`.
- لا يوجد Upload API (واجهة رفع) ولا خادم تخزين.
- لا ندّعي دعم PDF/DOCX في هذه المرحلة؛ يضاف لاحقاً فقط بعد اختيار Parser (محلل) آمن ومفتوح المصدر.

## Search / RAG (البحث والاسترجاع المعرفي)

### الفهرسة

النص يقسم إلى Chunks (مقاطع) بحجم يقارب 1100 حرف مع Overlap (تداخل) 180 حرفاً حتى لا تنقطع الجمل المهمة عند الحدود.

### الاسترجاع

النسخة الحالية تستخدم Local Lexical Retrieval (استرجاعاً لفظياً محلياً):
- Unicode normalization (تطبيع اليونيكود).
- إزالة تشكيل العربية لأغراض المطابقة فقط.
- Token matching (مطابقة الكلمات).
- Query coverage (نسبة تغطية كلمات السؤال).
- Exact phrase boost (تعزيز العبارة المطابقة).

لا نستخدم Vector DB (قاعدة متجهات) خارجية، ولا API Embeddings (واجهة تضمينات) مدفوعة.

### قبل تشغيل الوكيل

1. يأخذ النظام Task (المهمة) الأصلية.
2. يبحث في Long-Term Memory وKnowledge Chunks الخاصة بالوكيل.
3. يأخذ أعلى 6 نتائج فقط.
4. يضيف آخر 4 عناصر مناسبة من Session Memory.
5. يبني Augmented Prompt (تعليمات معززة بالسياق).
6. يرسل هذا السياق إلى Runtime (محرك التشغيل) المحلي.
7. Run Log (سجل التشغيل) يعرض المهمة الأصلية، لا النص الداخلي المعزز.

## Export / Delete (التصدير والحذف)

المستخدم يستطيع:
- Export Memory (تصدير الذاكرة) إلى ملف JSON محلي.
- حذف عنصر ذاكرة منفرد.
- حذف Knowledge File (ملف معرفة) وفهرسته.
- حذف كل ذاكرة ومعرفة الوكيل.
- مسح Session Memory (ذاكرة الجلسة).

## الخصوصية

- الذاكرة والفهرس في هذه المرحلة محليان على الجهاز.
- Local AI نفسه قد يحتاج الإنترنت لتنزيل أوزان النموذج أول مرة، لكن هذا منفصل عن قاعدة الذاكرة.
- لا يوجد مزود SaaS للذاكرة.
- لا توجد مفاتيح API مطلوبة للذاكرة أو RAG.

## حدود المرحلة الحالية

- localStorage مناسب للنواة الأولى، لكنه ليس مخزناً نهائياً لأحجام ضخمة.
- عند نمو المشروع سننقل التخزين المحلي إلى IndexedDB (قاعدة بيانات المتصفح) خلف Storage Adapter (موصل تخزين) مع Migration (ترحيل) آمن.
- البحث الحالي لفظي وليس Semantic Embeddings (تضمينات دلالية). هذا قرار مقصود للحفاظ على 0$ وخفة الهاتف أولاً.

## Security Gates (بوابات الأمان)

Phase 2 لا تُدمج إلا مع نجاح:
- Phase 0 validation.
- Phase 1 zero-cost validation.
- Phase 2 memory/knowledge validation.
- TypeScript + Production build.
- Production dependency audit عند مستوى High (عالٍ) أو أعلى.

ويمنع validator (الفاحص) إدخال SDKs (حزم) لقواعد ذاكرة/متجهات خارجية محددة إلى هذه المرحلة دون مراجعة معمارية جديدة.
