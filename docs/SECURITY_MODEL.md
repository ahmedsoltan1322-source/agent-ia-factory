# Security Model (نموذج الأمان)

## المبدأ

Agent IA Factory (مصنع وكلاء الذكاء الاصطناعي) يفترض أن Models (النماذج)، Tools (الأدوات)، MCP Servers (خوادم MCP)، صفحات الويب، والملفات الخارجية قد تكون غير موثوقة.

## Trust Boundaries (حدود الثقة)

1. **User (المستخدم):** صاحب القرار النهائي.
2. **Control Plane (طبقة التحكم):** موثوقة لكن يجب أن تُراجع وتُسجل أفعالها.
3. **Agent Runtime (محرك الوكيل):** شبه موثوق؛ لا يمتلك صلاحيات مباشرة خارج Policy Engine (محرك السياسات).
4. **Models (النماذج):** غير موثوقة لاتخاذ قرارات صلاحيات أو أسرار.
5. **Tools/MCP (الأدوات/MCP):** غير موثوقة حتى اجتياز الفحص.
6. **External Content (المحتوى الخارجي):** غير موثوق وقد يحتوي Prompt Injection (حقن تعليمات).

## قواعد إلزامية

### Secrets (الأسرار)
- ممنوع تخزين Secret (سر) في Git.
- ممنوع إدخال الأسرار في Prompt (التعليمات المرسلة للنموذج) إلا عبر آلية محدودة ومصرح بها عند الضرورة.
- كل Secret يجب أن يكون Scope-Limited (محدود النطاق) وقابلاً للإبطال.

### Least Privilege (أقل صلاحيات)
كل Agent وTool يحصل فقط على أقل صلاحيات لازمة للمهمة.

### Human Approval (موافقة بشرية)
تتطلب موافقة بشرية افتراضياً:
- إرسال رسالة خارجية باسم المستخدم.
- نشر محتوى للعامة.
- حذف أو تعديل بيانات مهمة.
- تنفيذ عملية مالية.
- تثبيت Dependency (تبعية) جديدة في بيئة Production (الإنتاج).
- تغيير سياسات الأمن أو التكلفة.

### Prompt Injection Defense (الدفاع ضد حقن التعليمات)
- محتوى الويب والملفات = Data (بيانات)، وليس أوامر نظام.
- لا يسمح للنص الخارجي بتغيير صلاحيات Agent.
- الأداة الحساسة تحتاج Authorization Check (فحص تفويض) مستقل عن النموذج.

### Sandbox (العزل)
Code Execution (تشغيل الكود) وBrowser Automation (أتمتة المتصفح) يجب أن يملكا:
- حد CPU.
- حد RAM.
- Timeout (مهلة).
- Filesystem Isolation (عزل ملفات).
- Network Allowlist (قائمة سماح للشبكة) حيث أمكن.
- منع الوصول للأسرار غير المطلوبة.

## OSS Security Gate (بوابة أمان المصادر المفتوحة)

أي Repository (مستودع) خارجي يمر قبل الدمج عبر:
1. License Check (فحص الترخيص).
2. Activity/Maintenance Check (فحص النشاط والصيانة).
3. Dependency Audit (فحص التبعيات).
4. Known Vulnerability Scan (مسح الثغرات المعروفة).
5. Secret Scan (مسح الأسرار).
6. Static Analysis (تحليل ساكن) حيث ينطبق.
7. Sandbox Test (اختبار معزول).
8. Minimal-Permission Integration (دمج بأقل صلاحيات).
9. Pinned Version (نسخة مثبتة محددة).
10. Rollback Plan (خطة رجوع).

## Audit Log (سجل التدقيق)

الأفعال الحساسة تسجل:
- من طلب الفعل.
- أي Agent اقترحه.
- أي Tool نفذه.
- الوقت.
- البيانات الهدف دون كشف أسرار.
- هل احتاج موافقة؟ ومن وافق؟
- النتيجة.

## Security Invariants (ثوابت أمنية)

- Model output (مخرجات النموذج) لا يمنح صلاحيات.
- وجود API Key (مفتاح واجهة) لا يعني السماح باستعماله.
- لا Tool حساس بدون Policy Check (فحص سياسة).
- لا دفع تلقائي.
- لا أسرار في Logs (السجلات).
- لا ثقة بمشروع Open Source لمجرد شهرته.
