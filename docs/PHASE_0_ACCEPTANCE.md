# Phase 0 Acceptance (قبول المرحلة صفر)

لا تبدأ Phase 1 (المرحلة الأولى) رسمياً قبل تحقق جميع البنود التالية.

## Architecture (المعمارية)
- [x] تعريف Control Plane (طبقة التحكم).
- [x] تعريف Agent Core (نواة الوكيل).
- [x] فصل Runtime Adapters (موصلات التشغيل) عن النواة.
- [x] فصل Model Router (موجه النماذج) عن النواة.
- [x] تعريف Tool/MCP Layer (طبقة الأدوات وMCP).
- [x] تعريف Memory/Workflow/Policy/Sandbox/Evaluation layers.

## Cost (التكلفة)
- [x] Zero-Cost Policy (سياسة التكلفة الصفرية) موثقة.
- [x] Paid Execution (التشغيل المدفوع) معطل افتراضياً.
- [x] شرط Fail Closed (الفشل الآمن) عند تكلفة مجهولة.
- [x] الاشتراكات الحالية تُعامل كموارد تطوير وليست متطلبات تشغيل.

## Security (الأمان)
- [x] Trust Boundaries (حدود الثقة) محددة.
- [x] Human Approval (الموافقة البشرية) محددة للأفعال الحساسة.
- [x] OSS Security Gate (بوابة أمان المصادر المفتوحة) محددة.
- [x] Secrets Policy (سياسة الأسرار) موثقة.
- [x] Prompt Injection (حقن التعليمات) لا يمنح صلاحيات.

## Mobile (الهاتف)
- [x] Phone-Only Mode (وضع الهاتف فقط) موثق.
- [x] Terminal (سطر الأوامر) ليس شرطاً على المستخدم النهائي.
- [x] Arabic-First UX (تجربة عربية أولاً) مثبتة كقاعدة.

## Agent Contract (عقد الوكيل)
- [x] JSON Schema (مخطط JSON) أولي موجود.
- [x] يتضمن الهوية والتعليمات والنموذج والأدوات والذاكرة والصلاحيات والتكلفة والتقييم.

## OSS (المصادر المفتوحة)
- [x] Catalog (دليل) أولي موجود.
- [x] حالات القرار USE/ADAPT/STUDY/WATCH/REJECT معرفة.
- [ ] مراجعة تراخيص المرشحين واحداً واحداً قبل الدمج البرمجي.
- [ ] فحص أمني لكل Dependency (تبعية) عند تثبيت أول Runtime.

## شرط الانتقال

Phase 0 (المرحلة صفر) تعتبر **مقبولة مع بوابتين مفتوحتين** فقط: التحقق التفصيلي من تراخيص وأمان المشاريع يتم عند اختيار Dependencies (التبعيات) الفعلية في Phase 1، وليس بمجرد إدراجها كمرشحين.
